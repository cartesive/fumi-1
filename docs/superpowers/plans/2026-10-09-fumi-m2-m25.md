# FuMi-1 M2 + M2.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the FoMni fork into FuMi-1's pitch core (M2) and audition bench (M2.5): the measured ST-50 tuning, 本数 mapping, click-free control smoothing, bend-button logic, Felucca's FM6 engine on the host and in the browser, and a playable browser bench for voicing the koto.

**Architecture:** FoMni's shape is kept: `firmware/src/dsp/fumi.c` is one -O2 unit (the instrument, including the FM6 core and the reverb), `firmware/src/app/ui.c` is the panel and screen, `host/fumi_host.c` runs the whole app on a Mac from a script, `web/emu/fumi_web.c` compiles the same to WebAssembly. The bench (`web/bench/`) is that WebAssembly plus bench-only exports (patch set/get, voicing parameters, note on/off) driven from a page. All pitch maths is float cents; the FM6 core takes a Q24 log2 frequency computed once per block per voice.

**Tech Stack:** C99 (no `double` in firmware code), Python 3.13 (tools, analysis: numpy/scipy), Emscripten (bench and emulator), plain JS (Web Audio worklet, Web MIDI).

**Spec:** Dropbox `projects_2026/ST50/00-START-HERE.md` (current truth), `03-flashing-safety.md` (hard rules), `13`, `14` (measurements), `16-audition-bench.md`, `06` (bend buttons), `tuning-reference.md` (formula). Copies are in `docs/research/` (this repo).

## Global Constraints

- Never modify `firmware/hal/`, `firmware/loader/`, `firmware/src/{ota,usb,storage,lcd,gfx,libc,midi_uart}.c`, `firmware/crt0.S`, `tools/fm1pkg_make.py`, `tools/fm1_install.py`, `tools/fm1_rescue.py`, `tools/fm1_rescue.sh`, `web/fm1ota.js`, `web/fm1pkg.js`. `tools/guard_platform.sh` enforces this against FoMni commit `b81eb6b661c35948ec2d1059664d4e5790999305`.
- OCT− + OCT+ held together stays update mode; bend logic ignores the both-held state.
- No `double` in `firmware/src/app/` or `firmware/src/dsp/` (tests may use it). `-Wdouble-promotion -Werror` on the DSP host test build.
- Nothing read from flash is trusted without length and CRC checks (FoMni's `project_valid` pattern).
- No Yamaha ROM patch data and no ST-50 audio in the tree. `refs/` is git-ignored.
- Anything unmeasured (fa♯, sol, do♯, re offsets in SUIKO; the 本数 assumption) is a table with a comment, not a constant buried in code.
- Package identity for dev builds: `FM-1_700` (to confirm against awesome-fm-1 before release).

## Review Focus

1. A tuning switch (平均律 ↔ 純正律) while a note rings must not click: the offset goes through the smoother (click test, Task 7).
2. OCT+ pressed with a note held, then the note released before the button: the bend must end cleanly and the button must not become an octave shift on release (bend test, Task 6).
3. A DX7 `.syx` with a bad checksum or wrong length must be refused, not loaded half-way (syx test, Task 10).
4. 本数 at 水4 with octave down and white key 1: the lowest note (F1) must still be inside the FM6 range and in tune (tuning + fm6 pitch test, Task 8).
5. Eight voices held with reverb: the host render must stay under the device budget estimate and never exceed full scale (fumi test, Task 9).

## Tasks

### Task 2: Rename the instrument files and the package
- `firmware/src/dsp/omni.{c,h}` → `fumi.{c,h}` (a stub instrument that renders silence, with `fm_*` API), `host/omni_host.c` → `fumi_host.c`, `web/emu/omni_web.c` → `fumi_web.c`, `tools/build.py` O2_UNITS/outputs/PRODUCT, `tests/run_tests.sh`, `host/build_host.sh`, `web/emu/build.sh`, `main.c` FELUCCA_ID default, `app/*` strings. - Test: host builds, emulator builds, `./build.sh` makes `build/fumi.fwsc` with identity `FM-1_700`.

### Task 3: tuning.c (TDD)
- Tests (`tests/host/tuning_test.c`, double allowed): SUIKO offsets (fa −20.8, do −16.0, ti♭ −25) scale with depth; KOTO offsets (−9.8, −2.0, +2.0, −7.8); 1本 white key 0 = A2 = 110 Hz (−2400 cents from A4) and white key 5 (三) = 220 Hz; 水4 → 三 = F3; 12本 → 三 = G♯4; every white key × 16 本 × TN_EQUAL equals `100 * (53 + hon + 12*(w/5 - 1) - 69) + scale[w%5]`; YŌ and MIN'YŌ tables; fine ±50 and octave ±1; black keys in upper-row mode; A4 = 442.
- All within 1e-4 cents.

### Task 4: smooth.c (TDD)
- Tests: a step of 100 cents reaches 63 % at the time constant (±10 %), never exceeds slew limit per block, converges within 1e-3; `smooth_jump` is immediate.

### Task 5: FM6 core on the host (TDD)
- `tools/gen_fm6_tables.py` writes `fm6_tables.h` (SINE 1025, FM6_EXP2, LFO_DELTA, DETUNE, FINE, constants) for CTL 32. Port `fm6_core.c` from Felucca (header kept, note the changes). Add `fm6_logfreq_cents`.
- Tests (`tests/host/fm6_test.c`): a one-carrier patch (OP1 ratio 1, level 99, others 0) at 440 Hz renders a sine whose YIN pitch is 440 ± 0.5 Hz; at 1本 three octaves; pack/unpack round trip for 100 random packed records; every operator-on patch gives peak < 1.0 and |mean| < 1 %; envelope releases to silence; `fm6_note_done` goes true after release.

### Task 6: bend.c (TDD)
- Tests: press OCT+ with no note → returns 0 (octave); with a note → 1 and bend rises to +100 over ~90 ms with an S-curve (value at 45 ms between 40 and 60 cents), holds, falls over ~120 ms after release; tap (down/up within 60 ms) does a full up-and-back flick; OCT− gives −40; both held → `bend_button` returns 0 for both and bend output goes to 0; note released before the button: bend decays, release of the button is not an octave change.

### Task 7: fumi.c, the instrument (TDD)
- Voices: 8, FM6 notes with a per-voice amplitude envelope for 余韻 (key-up: release time 20 ms … 8 s), vibrato LFO (rate 0.5–8 Hz, depth 0–50 cents), trill (re-trigger the held note every 60–400 ms with ±jitter), mono/poly, pitch = tuning + smoother(bend + tuning switch) + vibrato; low cut (one-pole HP 20–400 Hz), high cut (two-pole LP 1–16 kHz), character (tilt + soft saturation amount), reverb (plate, send + size), output limiter (soft clip).
- Params (`FP_*` enum in fumi.h): HON, SCALE, TUNING, DEPTH, FINE, A4, OCTAVE, YOIN, VIB_RATE, VIB_DEPTH, VIB_ON, TRILL_ON, TRILL_RATE, TRILL_VAR, MONO, BLACK_MODE, BEND_UP, BEND_DOWN, SLIDE, LOWCUT, HIGHCUT, CHARACTER, REVERB, REV_SIZE, VOICE, MIDI_OUT, LEDS, plus USER_T0..9.
- Tests (`tests/host/fumi_test.c`): key 5 at 1本 gives YIN 220 ± 1 Hz; tuning SUIKO moves white key 1 by −20.8 cents (YIN within 1 cent); 8 keys held + reverb peak < 1.0; 余韻 min silences within 100 ms of key-up, max keeps ringing after 1 s; trill re-triggers (count onsets); mono steals.
- Click regression test (`tests/host/click_test.c`): a held note while the script applies bend steps, a tuning switch, 本数 change, voice steal; fail if any sample-to-sample jump exceeds 4× the running RMS slope or HF (>5 kHz) energy in the 5 ms after an event exceeds 6× the preceding 50 ms. Prove it fails with the smoother bypassed (`-DFM_NO_SMOOTH`).

### Task 8: app (ui.c, project.c) and the host simulator

### Task 9: web emulator build + bench core
- `web/emu/fumi_web.c` exports FoMni's set plus `web_patch_set/get`, `web_param(int, int)`, `web_note(note, on, cents)`, `web_peak()`. Worklet unchanged in shape. `tests/host/emu_test.mjs` updated.
- `web/bench/`: the page: on-screen keys in FuMi's layout, computer keyboard (Q–I, A–K whites; 1–0, − blacks), Web MIDI in; a patch list (click or number key = instant switch), A/B and blind A/B, morph slider (per-byte interpolation of the two 155-byte patches with level/rate bytes interpolated and discrete bytes taken from the nearer side), live sliders for every patch byte grouped by operator, voicing sliders (low cut, high cut, character, reverb, size, 余韻), 本数 / 調律 / depth controls, stock phrases (single notes ×3 registers, slow overlapping phrase, fast gliss, bend), reference clips from `refs/` on a button with level matching (RMS), notes + star rating per patch with prompts, autosave to localStorage, export of the session as JSON into `bench/sessions/`, export of chosen patches as a 32-voice DX7 `.syx`.

### Task 10: tools
